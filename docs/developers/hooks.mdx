# Hooks reference

All Stitch-specific filters use the `woocommerce_stitch_*` prefix unless noted. Most filters receive the `Gateway` instance as the second parameter.

## Filters

### `woocommerce_stitch_payment_form_template_args`

Filter arguments passed to the classic `payment-form.php` template.

### `woocommerce_stitch_checkout_field_labels`

Filter field labels (`card_number`, `expiry`, `cvv`, `cardholder_name`).

```php
add_filter( 'woocommerce_stitch_checkout_field_labels', function ( $labels, $gateway ) {
	$labels['card_number'] = 'Card #';
	return $labels;
}, 10, 2 );
```

### `woocommerce_stitch_checkout_display_settings`

Filter branding: `show_logo`, `show_card_icons`, `show_description`, `description`, `logo_url`.

### `woocommerce_stitch_payment_form_i18n`

Filter all UI, validation, and surcharge strings for classic checkout, Blocks, and classic JS.

### `woocommerce_stitch_saved_payment_methods`

Filter saved methods (keyed by account ID) before display on classic and Blocks checkout.

### `woocommerce_stitch_accepted_card_brands`

Filter card brand slugs in the payment header. Default: `visa`, `mastercard`, `amex`, `discover`.

### `woocommerce_stitch_payment_header_html`

Filter rendered header HTML (logo, icons, description). Output is sanitized with `Card_Icons::kses_payment_header_html()`.

### `woocommerce_stitch_iframe_css`

Filter minified CSS for the CardPointe tokenizer iframe. Since 0.4.0 this CSS is generated from the active [checkout style preset](#woocommerce_stitch_style_presets), so the inner card-number field matches the rest of the form; the filter still runs last as an escape hatch. See [CardPointe tokenizer docs](https://developer.cardpointe.com/hosted-iframe-tokenizer).

### `woocommerce_stitch_style_presets`

_Since 0.4.0._ Register or modify the checkout style presets offered by the **Checkout style** setting. Each preset has a translated `label` and a `tokens` map of `--stitch-*` CSS custom property overrides; tokens you omit keep the stylesheet defaults. Built-in presets: `default`, `minimal`, `compact`, `dark`.

```php
add_filter( 'woocommerce_stitch_style_presets', function ( $presets ) {
	$presets['brand'] = array(
		'label'  => __( 'Brand', 'my-theme' ),
		'tokens' => array(
			'--stitch-accent'       => '#ff6600',
			'--stitch-radius-sm'    => '2px',
			'--stitch-field-height' => '44px',
		),
	);
	return $presets;
} );
```

Merchants can also set an **Accent color** and **Custom checkout CSS** directly in the gateway settings — both are printed after the preset overrides, so they win over preset values. Themes that only need small tweaks can skip presets entirely and override the variables in CSS — the form stylesheet declares every token on `:root`:

```css
:root {
	--stitch-accent: #ff6600;
	--stitch-radius-sm: 2px;
}
```

Available tokens: `--stitch-accent`, `--stitch-accent-soft`, `--stitch-focus-ring`, `--stitch-success`, `--stitch-error`, `--stitch-error-ring`, `--stitch-surface`, `--stitch-surface-soft`, `--stitch-form-bg`, `--stitch-form-padding`, `--stitch-form-text`, `--stitch-text-body`, `--stitch-text-muted`, `--stitch-field-text`, `--stitch-field-placeholder`, `--stitch-field-border`, `--stitch-border-soft`, `--stitch-saved-border`, `--stitch-header-bg`, `--stitch-header-padding`, `--stitch-radius-sm`, `--stitch-radius-md`, `--stitch-radius-lg`, `--stitch-field-height`, `--stitch-field-padding`, `--stitch-row-gap`, `--stitch-card-preview-bg`.

The `--stitch-field-height`, `--stitch-field-text`, and `--stitch-field-placeholder` tokens also drive the CardPointe iframe field when set through a preset. Plain CSS variable overrides cannot reach inside the iframe — use a preset or the `woocommerce_stitch_iframe_css` filter for that.

### `woocommerce_stitch_gateway_script_params`

Filter `wc_stitch_params` for classic checkout JS.

### `woocommerce_stitch_blocks_payment_method_data`

Filter all data passed to `stitch-blocks.js`.

### `woocommerce_stitch_is_checkout_context`

Filter whether the current request is a checkout/payment-form context (used for asset loading).

### `woocommerce_stitch_should_enqueue_payment_assets`

Filter whether CSS/JS are enqueued. Defaults to `Checkout_Context::is_checkout_context()`.

### `woocommerce_stitch_hide_native_saved_methods`

_Since 0.3.2._ Filter whether saved Stitch cards are hidden from WooCommerce's own top-level saved-method options at checkout (rendered by the Blocks checkout above the payment method list). Defaults to `true` because paying through that native option bypasses the Stitch payment form and its surcharge disclosure — saved cards are instead selected inside the Stitch payment method. Return `false` to restore the native options (not recommended when surcharge disclosure is enabled). My Account → Payment methods is not affected either way.

```php
// Restore WooCommerce's native saved-card options at checkout.
add_filter( 'woocommerce_stitch_hide_native_saved_methods', '__return_false' );
```

### `woocommerce_stitch_register_gateway`

_Since 0.3.0._ Filter whether the Stitch gateway is registered with WooCommerce. Returning `false` removes both the classic and Blocks payment methods — useful for staging environments or conditional rollouts. Defaults to `true`.

```php
// Disable Stitch on staging only.
add_filter( 'woocommerce_stitch_register_gateway', function ( $register ) {
	return ( defined( 'WP_ENVIRONMENT_TYPE' ) && 'staging' === WP_ENVIRONMENT_TYPE )
		? false
		: $register;
} );
```

## Actions (classic checkout only)

| Hook | When |
|------|------|
| `woocommerce_stitch_before_payment_form` | Before the payment `<fieldset>` |
| `woocommerce_stitch_after_payment_header` | After logo / icons / description |
| `woocommerce_stitch_before_new_card_fields` | Before new card inputs |
| `woocommerce_stitch_after_payment_form` | After the `</fieldset>` |

```php
add_action( 'woocommerce_stitch_before_payment_form', function ( $gateway, $saved_methods ) {
	echo '<p class="stitch-checkout-notice">Cards are processed securely.</p>';
}, 10, 2 );
```

## Bootstrap

### `stitch_payments_loaded`

Fires after the plugin has loaded core services.

## Blocks vs classic

| Feature | Classic | Blocks |
|---------|---------|--------|
| PHP template override | Yes | No |
| Action hooks | Yes | No |
| `woocommerce_stitch_payment_form_i18n` | Yes | Yes |
| `woocommerce_stitch_saved_payment_methods` | Yes | Yes |
| `woocommerce_stitch_blocks_payment_method_data` | No | Yes |
| `woocommerce_stitch_gateway_script_params` | Yes | Shared JS dependency |

Prefer `woocommerce_stitch_payment_form_i18n` and `woocommerce_stitch_saved_payment_methods` when you need both checkout types to stay aligned.
