# Install Stitch Payments on WooCommerce

Follow these steps to install and configure Stitch Payments on your WooCommerce store.

<MerchantSignup>
  if you do not have a merchant account yet. Stitch sends the merchant ID and API credentials used below.
</MerchantSignup>

## 1. Install the plugin

1. Upload `stitch-payments-for-woocommerce` to `wp-content/plugins/`, or install from your distribution package.
2. Ensure **WooCommerce** is installed and active.
3. Activate **Stitch Payments for WooCommerce** from the WordPress **Plugins** screen.

Activation checks PHP version and WooCommerce availability. If a dependency is missing, the plugin will not activate.

## 2. Obtain credentials

Contact [Stitch Payments](https://www.stitchpayments.net/) to set up your merchant account and receive:

- Merchant ID (the numeric card merchant ID, not an ACH processor ID)
- API username and password
- Test (UAT) and production base URLs as applicable

The API host must be a CardPointe hostname. See [CardPointe references](/docs/developers/cardpointe) for the UAT host, the tokenizer, and the public CardPointe guides.

## 3. Configure the gateway

Go to **WooCommerce → Settings → Payments → Stitch**.

![Stitch gateway settings. The gateway is enabled and Test Mode is on. The checkout preview sits on the right.](/img/docs/admin-settings.png)

### Enable the gateway

1. Check **Enable Stitch Payment Gateway**.
2. Set the **Title** and **Description** customers see at checkout.

:::info USD only
The gateway processes payments in **USD**. If your store currency is set to anything else, Stitch is automatically hidden at checkout — check **WooCommerce → Settings → General → Currency** if the payment method does not appear.
:::

### API credentials

1. Open the **API Credentials** section.
2. Use the **Test** tab for UAT credentials and **Production** for live credentials.
3. Enable **Test Mode** while testing — the active tab should match the environment you are using.
4. Save changes. Credential validation runs on save.

![API credentials with Test Mode on. The merchant ID and username are hidden here. A saved password is not shown again, so that field stays blank.](/img/docs/admin-credentials.png)

:::note Saved passwords
For security, saved API passwords are not shown or pre-filled when you revisit the settings page. **Leave a password field blank to keep the current password** — only enter a value when you want to change it.
:::

:::note Base URL overrides
The optional test/production base URL fields only accept CardPointe hosts (`cardconnect.com` / `cardpointe.com`), entered as a bare hostname such as `fts-uat.cardconnect.com`. Anything else is ignored and the default endpoint is used, so your API credentials can never be sent to the wrong host by a typo. White-label hosts can be allowed by a developer via the [`woocommerce_stitch_allowed_api_hosts`](/docs/developers/hooks#woocommerce_stitch_allowed_api_hosts) filter.
:::

### Checkout display (optional)

Use the **Checkout display** section and the live preview on the right to tune the form: pick a **Checkout style** preset (Default, Minimal, Compact, or Dark), optionally set an **Accent color** or **Custom checkout CSS**, and adjust branding (logo, card icons, description, card preview, custom logo URL, field labels). The preview restyles as you type. See [Checkout display](/docs/merchants/checkout-display).

### Other settings

Under **Other settings** you can enable stored payment methods, choose whether to **charge immediately or authorize only** (see [Authorize and capture](/docs/merchants/authorize-and-capture)), send [Level 2 / 3 commercial data](/docs/merchants/commercial-data), set [address check (AVS) and CVV no-match](/docs/merchants/card-checks) actions, enable surcharge disclosure, and turn on enhanced debug logging.

![Other settings for saved cards, charge or authorize-only, Level 2/3 data, address and CVV checks, and surcharge.](/img/docs/admin-other-settings.png)

Stored payments and surcharge are documented in their own guides. Enhanced debug logging adds customer details (email, name, postal code) to payment log entries — keep it off in production unless support asks for it.

### Data retention

Scroll to **Data Retention** to review what the plugin stores and optionally enable removal of plugin data on uninstall. Use the in-settings summary when updating your privacy policy — details in [Data and privacy](/docs/merchants/data-and-privacy).

## 4. Test checkout

1. Keep **Test Mode** enabled.
2. Place a test order on classic checkout and, if used, Blocks checkout.
3. Use a CardPointe UAT test card. Any future expiry and any 3-digit security code (4 digits for American Express) are accepted. These approval numbers are from the [CardPointe UAT guide](https://developer.cardpointe.com/guides/cardpointe-gateway):

   | Brand | Test number |
   | --- | --- |
   | Visa | 4788250000121443 |
   | Mastercard | 5454545454545454 |
   | American Express | 371449635398431 |

   A 16-digit Visa number that passes the Luhn check, such as 4111111111111111, is also approved in UAT. Test numbers are declined in production.
4. A successful charge moves the order to **Processing**. The order note reads **Stitch payment successful**, followed by the transaction reference and auth code. The Stitch box on the order shows the same transaction reference.
5. Test a **guest** checkout with a new card, and a logged-in checkout with a saved card if **Enable Stored Payment Methods** is on.
6. If **Transaction type** is Authorize only, the order stays **On hold** and the note says the payment is authorized and not yet captured. Move one order to Processing or Completed to capture it, and cancel another to void the hold.

## 5. Go live

1. Enter production credentials in the **Production** tab.
2. Disable **Test Mode**.
3. Save and place a small live transaction to confirm end-to-end flow.
